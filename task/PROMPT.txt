开发一个本地认证器登记委员会模拟器。员工通过多名独立见证员确认后登记一枚合成认证器，委员会可以交接，设备历史要可审计。环境为 Windows 原生 Python 3.12、标准库与 SQLite，无外部依赖。身份、设备指纹和审批都使用虚构测试数据，无需实现签名算法或接触系统进程。提供 init、apply、inspect、verify 命令。

委员会配置定义版本、见证员及所属独立组、所需组数和负责人组。预约固定账户、设备指纹、预约 ID、登记截止时钟及创建时的配置版本。approve 必须绑定预约和当前配置版本，同一见证员重复同一审批幂等，变更内容冲突；有效见证按组去重，必须覆盖负责人组。撤销见证员仅在下一条事件起生效，此后该见证员尚未兑现的审批失效，已完成登记保留历史。普通切换使所有旧预约进入待转交，转交要求旧版本满足见证门槛并另有新版本负责人确认；两边共享的组可以各用于本版本的门槛，却不能由同一人同时满足两边负责人资格。已撤销人员不能确认。一次预约只能转交一次，转交后必须重新收集新版本见证。逻辑时钟由事件驱动，clock 等于截止值时失效，与配置切换同一 tick 按事件序号判定。已登记设备指纹全局只能对应一个当前账户，禁止把被撤销登记直接重新激活。

apply 读取 JSON 批并原子保存。第一个兑现成功者占设备，失败原因必须区分过期、门槛不足、未转交、设备已被占用；输入无效则整批回滚，合法业务拒绝记入可查询回执。两进程以同一存储并发提交时，不能重复兑现、产生部分记录或把失败批提前发布。重启后用原事件重建可见状态，逐阶段记录稳定的见证证据。

交付 README、夹具和自动化测试。覆盖跨组人员变更、两版本负责人为同一人、撤销与兑现交错、同 tick 边界、双账户争同一设备及在批次尾故障后重试。用小状态枚举独立核验转交和兑现结果。
